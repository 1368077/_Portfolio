壱作品概要Overview

荒廃した世界を舞台に、ウィルスに侵されたロボットと戦っていく3Dアクションゲームです。

ゴーストタウンとカテドラルの2ステージを収録。ステージ内の敵をすべて倒すとクリアで、結果に応じてランクが付きます。

3Dを学び始めて数か月の時期に制作した作品で、「今の自分にできる全力は何か」を模索しながら作りました。

弐技術的なこだわりTechnical Points

Point 01

構造体とJSONによる敵の生成・フェーズ配置エディタ

敵の種類や配置などのパラメータを構造体にまとめて std::vector で管理し、JSONから読み込んで生成しています。ステージの敵配置は「フェーズ → グループ」の単位で持たせ、ImGuiで作ったエネミーエディタから、フェーズごとに配置の追加・削除・保存・再読み込みができます。

本作ではファクトリーパターンを使わずに生成していますが、この仕組みをリファクタリングしてファクトリーパターンを組み込んだものが、次作『幽世縁起』の生成処理になっています。

  • 構造体 + std::vector
  • json.hpp
  • ImGui

Point 02

テンプレートのステートマシンで敵の行動を管理

敵の行動は、ステートマシン用のテンプレートクラスで管理しています。学内のゲーム技研部の記事 「C++で汎用的な状態管理クラスを実装する方法」をもとに作りました。

状態の持ち主をテンプレート引数で指定するので、各ステートから持ち主の敵へ安全にアクセスできます。新しい行動を追加するときも、ステートのクラスを1つ増やすだけで済みます。プレイヤー側では、踏み込みながら攻撃する動きにも挑戦しました。

  • ステートマシン
  • C++ テンプレート

Point 03

Steam実績の実装

Steamworks SDKのサンプルプログラムを参考に、実績の解除処理を実装しました。デバッグ用に、ImGuiで実績の状態確認やリセットができる画面も用意しています。

※ リリース版には組み込んでいません

  • Steamworks API
  • Steam Input

Point 04

光が走るシェーダー

回路のようなロボット感を出すにはどうすればよいかUV値で光る方向を指定しかっこよくを意識して作りました。

  • HLSL

参苦労した点Problems & Solutions

Steam経由だとコントローラーが認識されない

課題
Steamの実績処理を組み込んで起動したところ、自作の入力処理でコントローラーが正しく認識されなくなった。
原因
Steam Inputが有効だと、コントローラーのユーザーインデックスがSteam側で変わる。自作の処理は元の番号を前提にしていたため、入力を拾えていなかった。
学び
独自の入力処理を入れるなら、Steam Inputの有効・無効を判定し、それぞれに合わせたフォールバック処理を用意する必要があると学んだ。

肆開発秘話Behind the Scenes

3Dを学んで数か月の「全力」

本作は、3Dを学び始めてまだ数か月の時期に作りました。できることが限られている中で「今の自分にできる全力は何か」を考え、踏み込みながら攻撃する動きなど、触って気持ちいい部分に挑戦しています。 爽快感という点で違和感は天敵で違和感を消す為にクロスフェードアニメーションを実装しました。 またプレイヤーが走るときは視野角を広げる処理を実装して爽快感を再現しました。

次の作品へのつながり

構造体とJSONで敵を生成する仕組みは、作っているうちに「種類が増えると分岐が膨らむ」ことに気づきました。その反省から、次作『幽世縁起』ではファクトリーパターンを組み込んだ形にリファクタリングしています。 ボリュームを出したい、続きが出せるなどの設計は我が子同然のような作品に一発芸人になってほしくない！！という思いやゲームとは動くだけがゲームなのかを自問自答し今の設計思想になっています。

リリースには入れなかったSteam対応

Steam実績はリリース版には入れていませんが、実装してみたことで、プラットフォームの機能が入力まわりのような思わぬところに影響することを知れました。 独自のフレームワークを作るときはGitHubでsteamブランチを作ってプラットフォームごとに作りやすい設計をしようと思いました。
